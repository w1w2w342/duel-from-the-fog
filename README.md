# DUEL FROM THE FOG
### Technical Project Overview

**DUEL FROM THE FOG** — многопользовательский трёхмерный шутер от первого лица (Multiplayer First-Person Shooter, FPS), разработанный на базе языка программирования Python. Проект ориентирован на соревновательный игровой процесс, построенный вокруг динамичных дуэльных столкновений, ограниченной видимости и тактического взаимодействия игроков.

Ключевой особенностью игры является использование атмосферного тумана в качестве основного элемента игрового дизайна. Ограниченная дальность визуального обнаружения противников повышает значимость позиционирования, пространственной ориентации, реакции и анализа звуковой информации.

Проект включает собственную клиент-серверную архитектуру, систему игровых режимов, модульную модель вооружения, набор трёхмерных карт, отдельный графический лаунчер и подсистему сбора игровой статистики.

---

## 1. Игровая концепция и режимы

**Жанр:** Multiplayer Tactical FPS.

**Перспектива:** First-Person (от первого лица).

**Игровая среда:** Трёхмерные боевые арены с ограниченной видимостью, различной геометрией и системой пространственных препятствий.

### 1.1. Игровые режимы

**FFA (Free For All)**

Индивидуальный соревновательный режим, в котором каждый участник самостоятельно противостоит остальным игрокам. Командное разделение отсутствует. Основная задача — первым достичь установленного порога в 5 устранений.

**TDM (Team Deathmatch)**

Командный режим с разделением участников на две противоборствующие стороны: Red Team и Blue Team. Победа определяется достижением командного лимита в 8 очков либо завершением установленного временного интервала продолжительностью 5 минут.

**ARMS RACE**

Режим последовательной смены вооружения с автоматическим возрождением после устранения. Каждое результативное устранение открывает следующий тип оружия в установленной последовательности. Условие завершения матча — достижение отметки в 20 устранений.

## 2. Технологический стек и архитектура

Архитектура DUEL FROM THE FOG построена на базе Python-экосистемы и предусматривает разделение игровых, сетевых, графических и пользовательских подсистем.

| Компонент | Технология | Назначение |
|---|---|---|
| Основной язык | Python 3 | Реализация игровой логики, серверной инфраструктуры, управления состоянием игровых объектов и обработки событий |
| 3D-движок | Ursina Engine / Panda3D | Рендеринг трёхмерной сцены, обработка коллизий, управление камерой, освещением и графическими эффектами |
| Пользовательский интерфейс | PyQt6 | Разработка автономного лаунчера, конфигурационных окон, экранов подключения и управления параметрами клиента |
| Сетевой уровень | Python Sockets | Организация TCP/UDP-коммуникации между игровыми клиентами и серверной частью |
| Обработка данных | ujson | Сериализация и десериализация сетевых сообщений и структурированных данных |
| Многопоточность | threading | Организация параллельного выполнения отдельных серверных и клиентских задач |
| Discord Integration | pypresence / Discord RPC | Интеграция с Discord Rich Presence для отображения игрового статуса |
| Форматы 3D-ресурсов | OBJ, MTL, glTF | Импорт трёхмерных моделей, материалов, игровых объектов и элементов окружения |
| Аудиоподсистема | Ursina Audio | Воспроизведение игровых звуков с учётом пространственного расположения источников |
| Система статистики | JSON / Custom Player Statistics | Хранение и обработка пользовательской статистики, результатов матчей и игровых показателей |

### 2.1. Клиент-серверная архитектура

В основе сетевого взаимодействия предусмотрена клиент-серверная модель, в которой сервер отвечает за координацию игрового процесса, синхронизацию состояний участников и обработку игровых событий.

Основные задачи серверной подсистемы:

- Обработка подключений и отключений игроков.
- Управление состоянием игровых сессий.
- Синхронизация позиций и состояний игровых объектов.
- Обработка игровых событий и результатов столкновений.
- Поддержка командных и индивидуальных игровых режимов.
- Управление игровыми раундами и условиями завершения матчей.

**Целевой показатель частоты серверного обновления — 128 Hz.** Данный параметр рассматривается как проектная характеристика сетевого цикла и требует подтверждения нагрузочным тестированием.

## 3. Система вооружения и игровая баллистика

Подсистема вооружения реализована с использованием модульного подхода, предусматривающего индивидуальные параметры каждого типа оружия, собственные механики стрельбы и характеристики нанесения урона.

### 3.1. Модель попаданий и хитбоксов

Игровые персонажи используют систему пространственного разделения зон регистрации попаданий:

- **Head** — область головы.
- **Body** — область корпуса.
- **Arms** — область рук.
- **Legs** — область ног.

Для отдельных зон предусматриваются различные коэффициенты урона. Попадания в голову имеют повышенный множитель относительно базового значения.

### 3.2. Арсенал

**M4A1 — Automatic Rifle**

Основная автоматическая винтовка, предназначенная для ведения огня на средних дистанциях. Предусмотрена система процедурной отдачи (Recoil System), изменяющая положение прицела по горизонтальной и вертикальной осям при непрерывной стрельбе.

**Sawed-Off — Shotgun**

Дробовик для ближнего боя. Баллистическая модель предусматривает распределение нескольких независимых дробовых снарядов (Pellets) в пределах заданного угла рассеивания. Один выстрел формирует 6 отдельных траекторий поражающих элементов.

**AWP — Sniper Rifle**

Крупнокалиберная снайперская винтовка, ориентированная на высокоточное поражение целей на значительных дистанциях. Базовая модель предусматривает нанесение до 100 единиц урона.

Реализуемые интерфейсные механики:

- Оптический прицел (Scope Interface).
- Изменение поля зрения камеры (FOV).
- Аудиосопровождение активации и деактивации прицела.
- Отдельная конфигурация параметров стрельбы.

**Revolver — Heavy Sidearm**

Тяжёлое короткоствольное оружие с дополнительными игровыми механиками:

- **Fan the Hammer** — альтернативный режим скоростной стрельбы.
- **Lucky Chamber** — дополнительная механика случайного выбора патрона с возможностью нанесения повышенного критического урона.

## 4. Игровые карты и система ротации

Игровое пространство представлено набором трёхмерных арен, различающихся архитектурой, размерами, конфигурацией укрытий и предполагаемой дистанцией взаимодействия между игроками.

### 4.1. Список игровых локаций

| Карта | Архитектурная концепция | Игровое назначение |
|---|---|---|
| dust2.obj | Классическая соревновательная карта с протяжёнными коридорами и открытыми площадками | Универсальные боевые столкновения |
| metro.obj | Закрытая станция метрополитена с колоннами и разветвлёнными переходами | Ближний и средний бой |
| awp_fite.obj | Симметричная открытая арена | Снайперские дуэли |
| nuclear.obj | Индустриальный комплекс с техническими помещениями и переходами | Тактическое взаимодействие |
| angar.obj | Компактное промышленное пространство | Динамичные контактные столкновения |
| paintball.obj | Симметричная тренировочная площадка с искусственными укрытиями | Тренировочные и соревновательные матчи |
| random_arena.obj | Экспериментальная процедурная или тестовая локация | Проверка игровых механик |
| my_map.obj | Пользовательская тестовая карта | Разработка и отладка игровых систем |

### 4.2. Map Voting System

После завершения игрового матча активируется система голосования за следующую карту.

Подсистема предусматривает:

- Формирование списка доступных карт.
- Отображение вариантов голосования.
- Регистрацию пользовательских голосов.
- Подсчёт результатов.
- Определение карты-победителя.
- Автоматическое переключение игровой сессии на выбранную локацию.

## 5. Графическая подсистема и пользовательский интерфейс

Клиентская часть проекта предусматривает систему конфигурации графических параметров, управления игровым интерфейсом и отображения актуальной информации о состоянии матча.

### 5.1. Графические настройки

Предусмотрены следующие пользовательские параметры:

- Режим отображения: Fullscreen / Windowed.
- Выбор разрешения экрана.
- Ограничение частоты кадров (FPS Limit).
- Управление вертикальной синхронизацией (VSync).
- Настройка цвета и визуальных параметров прицела.
- Конфигурация чувствительности мыши.

### 5.2. HUD — Heads-Up Display

Внутриигровой интерфейс предназначен для предоставления игроку актуальной информации без необходимости открытия дополнительных экранов.

Основные элементы:

**Scoreboard**

Информационная таблица, вызываемая клавишей TAB. Отображает список участников матча, их игровые показатели, сетевую задержку (Ping) и текущий счёт.

**Killfeed**

Динамическая система отображения событий устранения игроков. Информирует участников о результатах боевых столкновений в режиме реального времени.

**Match Information**

Информационный блок с текущими параметрами игровой сессии, включая режим, счёт и состояние матча.

## 6. Система пользовательских профилей и статистики

Для каждого игрока предусмотрена подсистема регистрации и обработки статистических показателей.

Основные параметры:

- **K/D Ratio** — соотношение устранений и смертей.
- **Total Kills** — общее количество устранений.
- **Total Deaths** — общее количество смертей.
- **Matches Played** — количество проведённых матчей.
- **Matches Won** — количество выигранных матчей.
- **Playtime** — суммарное игровое время.

Хранение статистических данных предусматривается с использованием структурированного формата JSON и специализированного модуля обработки пользовательских показателей.

## 7. Интеграция с Discord

Проект предусматривает интеграцию с Discord Rich Presence посредством библиотеки pypresence.

Интеграция предназначена для отображения актуального игрового статуса пользователя непосредственно в профиле Discord.

Предполагаемые отображаемые данные:

- Название игры.
- Текущий игровой режим.
- Название активной карты.
- Игровые показатели.
- Состояние игровой сессии.

## 8. Общая структура проекта

DUEL FROM THE FOG представляет собой программный комплекс, состоящий из нескольких взаимосвязанных подсистем:

1. **Game Client** — клиентское приложение, обеспечивающее визуализацию игрового мира, обработку пользовательского ввода и взаимодействие с сервером.
2. **Game Server** — серверная подсистема, отвечающая за управление игровыми сессиями и синхронизацию участников.
3. **Launcher** — автономное приложение для запуска игры, конфигурации параметров и подключения к игровым серверам.
4. **Gameplay Systems** — набор игровых механик, включающий управление персонажем, вооружение, баллистику, хитбоксы и игровые режимы.
5. **Map System** — подсистема загрузки, управления и ротации игровых карт.
6. **Statistics System** — модуль регистрации и обработки игровых результатов.
7. **Integration Layer** — дополнительные интеграционные компоненты, обеспечивающие взаимодействие с внешними сервисами.
